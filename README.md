## 🏢 Описание предметной области

Предметная область системы — **служба технической поддержки**, в которой регистрируются, рассматриваются и обрабатываются заявки пользователей. Программная система **«TechSupport»** представляет собой консольное приложение для автоматизации приёма и контроля исполнения обращений.

Система обеспечивает сопровождение жизненного цикла заявки через следующие ключевые статусы:
- 🟡 `Новая` — заявка зарегистрирована пользователем и ожидает назначения ответственного специалиста;
- 🔵 `В работе` — администратор принял заявку в работу и назначен исполнителем;
- 🟢 `Закрыта` — работы по обращению завершены, результат зафиксирован.

---

## 🎯 Цели и задачи системы

### Основная цель
Автоматизировать приём, систематизацию, учёт и контроль обработки заявок пользователей в службу технической поддержки.

### Задачи системы
- **Хранение сведений о пользователях**: регистрация учётных записей, хранение данных пользователей и администраторов.
- **Регистрация заявок**: фиксация темы, описания проблемы, категории обращения, приоритета и времени создания.
- **Управление статусами**: распределение заявок между администраторами, перевод по жизненному циклу.
- **Разграничение доступа**: строгое разделение функционала в зависимости от роли авторизованного актора.

---

## 👥 Роли пользователей и разграничение прав

В системе выделены два основных действующих лица (актора):

| Актор | Доступные действия | Условия доступа |
| :--- | :--- | :--- |
| **Пользователь** | • Самостоятельная регистрация<br>• Вход в систему (авторизация)<br>• Создание новой заявки<br>• Просмотр списка своих заявок<br>• Просмотр статуса конкретной заявки | Доступ к регистрации свободен; остальные действия — после авторизации |
| **Администратор** | • Авторизация в системе<br>• Регистрация новых администраторов<br>• Просмотр общего реестра всех заявок<br>• Фильтрация и сортировка обращений<br>• Назначение исполнителя на заявку<br>• Изменение рабочего статуса<br>• Закрытие выполненной заявки | Учётная запись первого администратора создаётся автоматически; доступ строго по логину и паролю |

## 🏛️ Архитектура системы

Проект спроектирован по **трёхуровневой архитектуре**:

1. **Слой представления (UI / Presentation Layer)**:
   - Консольный интерфейс пользователя и администратора, интерактивные меню ввода и вывода данных.
2. **Слой бизнес-логики (Business Logic Layer)**:
   - Валидация входных данных, проверка уникальности логинов, маршрутизация прав доступа, бизнес-правила изменения статусов заявок.
3. **Слой данных (Data Layer)**:
   - Структуры и хранилище сущностей системы (пользователи, заявки, категории, приоритеты).

## 📊 Моделирование процессов (PlantUML)

Диаграмма прецедентов (Use Case) спроектирована на языке **PlantUML** с учётом стандартов UML:
- Отношение между прецедентами *«Фильтровать и сортировать заявки»* и *«Просмотреть все заявки»* оформлено как **`<<extend>>`** (расширение), так как фильтрация является опциональным действием при просмотре реестра.
- Стрелка отношения `<<extend>>` направлена от дополнительного прецедента к базовому.

## 🚀 Инструкция по установке и запуску

### 1. Требования к окружению
- **Python** версии `3.10` или выше
- Установленная система контроля версий **Git**

### 2. Клонирование репозитория
```bash
git clone https://github.com/username/techsupport.git
cd techsupport
```

### 3. Развёртывание виртуального окружения (рекомендуется)
```bash
# Создание виртуального окружения
python -m venv venv

# Активация на Windows:
venv\Scripts\activate

# Активация на Linux/macOS:
source venv/bin/activate
```

### 4. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 5. Запуск приложения
```bash
python src/techsupport/main.py
```

*Ожидаемый результат выполнения:*
```text
hello world
```
